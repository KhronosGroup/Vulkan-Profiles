# Vulkan Profiles Checker (Android)

A small, dependency-light Android app that reports which *Vulkan Profiles* the device's driver supports and, for every unsupported profile, **exactly which requirements are not met** (missing extensions, disabled features, insufficient limits, unsupported format features, API version).

It also shows the GPU name, vendor/device IDs, the Vulkan API version, the raw and decoded driver version, and (when available) `VkPhysicalDeviceDriverProperties` (driver name, driver info, driver ID, conformance version), plus the Android system/SoC/driver-package properties.

## How it works

The app is a pure C++ `NativeActivity` (no Java/Kotlin code) built on top of the
[Vulkan Profiles API library](../../library/TUTORIAL.md) generated by this repository.

- At build time, CMake runs the repository's `scripts/vkprofiles.py` to generate a
  **debug** header-only profiles library for the selected profiles. The debug
  variant reports every unmet condition through `VP_DEBUG_MESSAGE_CALLBACK`.
- The app overrides that callback, captures the messages while calling
  `vpGetInstanceProfileSupport` / `vpGetPhysicalDeviceProfileVariantsSupport`,
  and groups them by *API version / Extensions / Features / Properties & limits / Formats*.
- The result is drawn with a tiny software renderer (system Roboto via `stb_truetype`)
  and also written to logcat and to the app's private `report.txt`.

Profiles included by default (see `VP_CHECKER_PROFILES` in [CMakeLists.txt](app/src/main/cpp/CMakeLists.txt)):

| Profile | Source |
|---|---|
| `VP_ANDROID_15_requirements`, `VP_ANDROID_16_requirements`, `VP_ANDROID_17_requirements`, `VP_ANDROID_18_requirements` | `profiles/Android/` |
| `VP_ANDROID_vulkan_profile_2021`, `VP_ANDROID_vulkan_profile_2022`, `VP_ANDROID_vulkan_profile_2025` | `profiles/Android/` |
| `VP_KHR_roadmap_2022`, `VP_KHR_roadmap_2024`, `VP_KHR_roadmap_2026` | Vulkan-Headers `registry/profiles/VP_KHR_roadmap.json` |

## Requirements

- Android SDK with platform 35 and the NDK (the version bundled with your AGP is fine)
- CMake 3.22.1 (installed through the SDK manager)
- JDK 17 or newer
- Python 3.10 or newer on `PATH` (used to run `vkprofiles.py`; `jsonschema`/`pyparsing` are installed into a private venv automatically)
- Network access during the first configure (Vulkan-Headers and `stb_truetype.h` are fetched and pinned)

## Build

```sh
cd android/profiles-checker
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

Or open `android/profiles-checker` in Android Studio.

> The app must be built from inside the Vulkan-Profiles checkout: the native build
> locates `scripts/vkprofiles.py` and `profiles/Android/*.json` relative to itself.

### Useful CMake options

Pass them via `android.defaultConfig.externalNativeBuild.cmake.arguments` in
`app/build.gradle.kts` or the Android Studio CMake settings:

| Option | Purpose |
|---|---|
| `-DVP_CHECKER_PROFILES=...` | Comma separated list of profiles to compile in |
| `-DVULKAN_HEADERS_GIT_TAG=v1.4.364` | Vulkan-Headers tag used for headers / `vk.xml` |
| `-DVULKAN_PROFILES_PREBUILT_HEADER=/path/to/vulkan_profiles.hpp` | Skip Python/generation and use an existing **debug** header |

## Reading the results

Each profile row shows **SUPPORTED** or **NOT SUPPORTED (N unmet)**. Tap a row to expand it:

- **Failing capability blocks** – the capability blocks of the profile that did not validate.
- **Unmet instance requirements** – API version / instance extension problems.
- **Unmet device requirements** – grouped item-level conditions reported by the profiles library, e.g.
  - `Extensions`: `VK_KHR_shader_float_controls`
  - `Features`: `VkPhysicalDeviceVulkan12Features::shaderInt8 == VK_TRUE`
  - `Properties & limits`: `VkPhysicalDeviceProperties2::properties.limits.maxImageDimension2D >= 8192`
  - `Formats`: `VK_FORMAT_R16_UNORM: VkFormatProperties2::formatProperties.bufferFeatures contains (VK_FORMAT_FEATURE_VERTEX_BUFFER_BIT)`

> For profiles with multiple variants, the list covers every variant the library
> evaluated; a profile is unsupported only when *no* variant validates.

The same content is available without the UI:

```sh
adb logcat -s VulkanProfilesChecker
adb shell run-as org.khronos.vulkanprofiles.checker cat files/report.txt
```

## Layout

```
android/profiles-checker/
├── app/src/main/AndroidManifest.xml      NativeActivity, hasCode="false"
├── app/src/main/cpp/CMakeLists.txt       FetchContent + header generation + native library
├── app/src/main/cpp/profile_checker.*    Drives the profiles library, captures debug messages
├── app/src/main/cpp/device_info.*        GPU / driver / system properties
├── app/src/main/cpp/report.*             Plain text report (logcat + report.txt)
├── app/src/main/cpp/text_renderer.*      stb_truetype software text rendering
├── app/src/main/cpp/ui.*                 Scrollable report view with tap-to-expand
└── app/src/main/cpp/main.cpp             android_main / event loop
```
